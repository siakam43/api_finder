# api-cleaner 2.5.b 单整数读取排除逻辑修正

## 问题

2.5.b "单整数读取排除" 与 2.4.c 旧版同源："仅读取了一个整数数据" 未区分**信道 API 读回的数据量**和**函数体实际使用的字段数**。当 `recv` 读回完整结构体但函数只用其中某个 int 成员时，可能误判为"单整数读取"而排除。

另外，2.5.b 引用 "2.4.c（整数型参数特殊处理）" 已过时——2.4.c 已改名。

## 设计

### 2.5.b 重写

**旧：**
```
#### b. 单整数读取排除

如果从信道**仅读取了一个整数数据**（且非内存地址），→ **排除**。

判断方式参考 2.4.c（整数型参数特殊处理）。从信道读取的大部分情况下是一整段 buffer 数据，如果仅读取单个整数（如状态寄存器值），安全影响较小。
```

**新：**
```
#### b. 单整数读取排除

如果从信道读取的原始数据**本身仅是一个整数**（且非内存地址）→ **排除**。
判断标准是信道 API 实际传输的数据量，不是函数体内实际使用了几个字段：

- `val = readl(MMIO_STATUS_REG)` → 读回单个 uint32，函数仅用 val 做位判断 → **单整数读取，排除**
- `recv(sock, buf, sizeof(struct req))` → 读回完整结构体，即使函数体内只用了 `buf.cmd_id` 一个成员 → **不是单整数读取，保留**。信道上传输的是完整结构体，安全影响不因使用量减少而消失
- `shmat(shmid)` + 强转 `(struct shm_data *)ptr` → 映射了整段共享内存，不是单整数读取

判断方式参考 2.4.c 中的内存地址判断规则（整数强转为指针、用于内存操作 → 保留）。
```

### 改动范围

仅 `api-cleaner/SKILL.md` 2.5.b 一节（约5行），不改其他部分。

## 预期效果

| 场景 | 当前行为 | 修正后行为 |
|------|---------|-----------|
| `readl(REG)` 读单个整数 | 正确排除 | 不变 |
| `recv(sock, buf, sizeof(struct req))`，只用 `buf.cmd_id` | 可能误判为单整数读取而排除 | 识别为结构体读取，保留 |
| `shmat` + 结构体强转 | 可能误判 | 识别为非单整数，保留 |
