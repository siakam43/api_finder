# api-cleaner 文件校验优化设计

## 问题背景

api-cleaner 消费 api-finder 的输出，但 api-finder 产出的接口可能存在：
1. `file` 字段不指向函数定义所在文件（如指向注册点位置）
2. 接口的 `file` 不在代码分析范围（scope_files）内

cleaner 应在分析前先校验这两点，避免对无效接口做无用分析。

## 设计方案

### 改动：2.1 读取源码后新增 2.1.1 文件校验子步骤

**位置：** `### 2.1 读取源码` 和 `### 2.2 快速排除检查` 之间

**流程：**

```
2.1 读取源码 → 2.1.1 文件校验 → 2.2 快速排除检查 → ...
```

**校验逻辑：**

1. **函数定义验证：** 确认 file 指向的文件中包含该函数定义。
   - 包含 → 通过
   - 不包含 → 在全部 scope_files 中搜索函数定义，找到则更新 file 并同步 analysis_state.json，找不到则排除（decision = "exclude"）

2. **分析范围验证：** 校验 file 是否在 scope_files 列表中。
   - 不在 → 排除（decision = "exclude"）

校验失败直接排除该接口，跳到下一个接口处理。校验通过才进入 2.2。

## 影响范围

- 仅修改 `api-cleaner/SKILL.md`
- 插入位置在 2.1 和 2.2 之间，不改动现有章节内容和顺序
- 不改变数据结构
