# api-cleaner 2.4 parameter_input 逻辑重构设计

## 问题描述

当前 SKILL.md 中 2.4 节的 parameter_input 深入分析存在逻辑边界不清的问题：

### 根因

1. **整数判断位置错误。** 2.4.b（逐参数外部输入判断）中嵌入了"该参数是整数型吗？→ 是 → 进入 c"的判断。这使得逐参数分类（b）和全局裁决（c）的职责交叉。

2. **排除范围扩大。** 当入参是一个 struct 指针时，函数体内从 struct 取了整数成员（如 `req->cmd_id`），LLM 分析时可能将 struct 指针内部的整数成员与参数本身的类型混为一谈，错误地将该接口归类为"仅有一个整数型外部输入参数"，触发 c 的非地址排除逻辑。

3. **指针判断冗余。** 2.4.b 的问题 3（是指针/缓冲区吗）在 b 步骤中做了应属于 c 的类型判断，与 b 的职责（筛选外部输入参数）不符。

### 表现

入参为 struct 指针、函数体内取用了整数成员的接口被错误排除。

---

## 设计方案

### 核心改动：b 做筛除，c 做裁决

**2.4.b — 锁定外部输入参数列表**

b 只做一件事：对每个入参回答两个问题，筛选出外部输入参数列表。

对函数签名中的每个入参逐一分析：

1. 该参数是系统框架类参数吗？（`struct file *f`、`struct inode *i`、内核内部数据结构指针、框架回调约定的上下文参数等）→ 是 → **内部参数，跳过**
2. 该参数用于输出目的吗？（`void *out_buffer`、`int *result`、`void *ret_data`），代码中对该参数仅写入不读取 → 是 → **内部参数，跳过**

两个都否 → 该参数为**外部输入参数**，加入列表。

统计外部输入参数列表：
- 个数 = 0 → **直接排除**（无外部输入），记录 reason
- 个数 > 0 → 记录参数名到 `taint_data` 字段（多个以 `/` 分割），进入 2.4.c

**2.4.c — 外部输入参数个数与类型裁决**

先统计外部输入参数个数，再决定是否做类型判断。**类型判断只看参数本身的 C 声明，绝不追踪函数体内从 struct/union 取出的成员类型：**

- `struct req *r` → 参数本身是指针，不是整数型，即使函数体内用了 `r->cmd_id`
- `void *data` → 参数本身是指针，不是整数型
- `int fd` → 参数本身是整数型

1. **个数 > 1**：多个外部输入参数，安全影响显著 → **无需额外判断，保留接口**

2. **个数 = 1**：唯一的外部输入参数，需判断其类型：
   - **非整数型**（指针、结构体指针、缓冲区、数组等）→ **保留接口**。指针类型本身就是外部数据的入口载体，无需进一步验证
   - **整数型**（含枚举、布尔）→ 需要判断该整数是否为内存地址。注意：判断的是参数自身的 C 类型声明（如 `int cmd`），不是函数体内从 struct 指针取出的整数成员（如 `req->cmd_id`），后者不改变参数本身是指针的事实：
     - 是内存地址 → **保留**
     - 非内存地址（仅作计数器、标志位、长度、命令码等）→ **排除**

3. **内存地址判断规则**（保留现有规则）：
   - 视为地址：参数类型为 `uintptr_t`、`unsigned long`、`size_t`，且在函数体内被显式强转为指针；或被用于解引用、`memcpy`/`copy_from_user` 等内存操作函数的地址参数位置
   - 视为普通值：仅用于算术运算、比较、位运算、switch/enum 匹配

## 改动范围

仅修改 `api-cleaner/SKILL.md` 中 2.4 节的两处：

### 2.4.b 改动

**删除：** 问题 3（指针/缓冲区判断）和问题 4（整数型判断）

**保留：** 问题 1（系统框架判断）和问题 2（输出目的判断）

**新增：** "两个都否 → 外部输入参数" 的显式结论，以及个数统计后的分支逻辑

### 2.4.c 改动

**标题改为：** "外部输入参数个数与类型裁决"

**重写内容：** 先 count，再分支：
- count > 1 → 保留
- count = 1 → 判类型（非整型保留，整型进入地址判断）

**保留：** 内存地址判断的具体规则不变

### 不改动的部分

- 2.4.a（内部调用者检查）— 不变
- 2.4.d（通信边界关联验证）— 不变
- 其他章节 — 不变

## 预期效果

| 场景 | 当前行为 | 修正后行为 |
|------|---------|-----------|
| `func(struct req *r)` — r 是外部输入，体内取用 `r->cmd_id`、`r->flags` | 可能误判为"仅一个整数型"而排除 | `r` 被正确归类为指针型外部输入，count=1 但非整型 → 保留 |
| `func(int fd)` — fd 是唯一外部输入 | 正确排除 | 不变 |
| `func(unsigned long addr)` — 体内强转为指针 | 正确保留 | 不变 |
| `func(void *buf, size_t len)` — 两个外部输入 | 正确保留 | 不变（count>1 直接保留，不进入类型判断） |
| `func(struct file *f, void *data)` — data 是外部输入，f 是框架参数 | 正确保留 | 不变（框架参数已被过滤） |
